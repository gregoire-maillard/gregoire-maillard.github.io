# Turkish A1 → C2 · Project spec

The rules for the Turkish section of gregoiremaillard.com. Every conversation that works on this section reads this file in full first, then the parts of [CURRICULUM.md](CURRICULUM.md) it needs, and finishes by adding a line to the progress log at the bottom.

**Contents:** 1 Goals · 2 Fixed decisions · 3 Files and pages · 4 IDs · 5 Data schemas · 6 Runtime behaviour · 7 Content style rules · 8 Validation · 9 Workflow for a conversation · 10 Progress log

## 1. Goals

- A complete Turkish course from A1 to C2 in the spirit of Duolingo: a path of units and short lessons, many small exercises, immediate feedback, XP and a streak.
- Every point of Turkish grammar and every verb form, explained in a grammar guide per unit and practised in that unit's lessons (scope in CURRICULUM.md).
- One culture or history interlude per unit, factual and neutral.
- A deck of the 1,000 most useful Turkish words, reviewed with Anki-style spaced repetition.
- Finished, correct content: natural Turkish, TDK spelling, accepted-answer lists that are fair to the learner.

**Not in scope:** accounts or a server, sync between devices (export and import instead), recorded audio, speech recognition, ads, leaderboards, any content copied from Duolingo or other courses.

## 2. Fixed decisions

| Topic | Decision |
|---|---|
| Hosting | Static files on GitHub Pages; no build step, no backend |
| Progress | `localStorage` in the learner's browser, with export to and import from a JSON file |
| Interface language | English only. All UI text, explanations and translations are in English; French appears only in an occasional comparison callout |
| Existing pages | `turkish101.html`, `learnturkish.html` and `movie.html` are left as they are and are not linked from the new section |
| Audio | The browser's Turkish text-to-speech voice (Web Speech API); no audio files |
| Flashcard algorithm | Anki's SM-2 variant with Anki's default settings (section 6.6) |
| Shared code | One script, `assets/js/turkish.js`, used by every page |
| Validation | `node scripts/turkish/validate.mjs`, no dependencies (section 8) |
| Git | Never commit or push; Grégoire reviews and pushes himself |

### Page conventions (for the build conversations)

- Pages sit at the site root like every other page. Copy the `<head>` pattern from `mtlmobility.html`: Google tag snippet, `meta description`, `canonical`, `og:` tags, favicon, viewport. `<html lang="en">`.
- The sticky glass header `.at-hdr` from `mtlmobility.html`, with the section's own tabs: **Course** (`turkish.html`), **Grammar** (`turkishguide.html`), **Flashcards** (`turkishcards.html`), `aria-current="page"` on the active one. The existing CSS hides tabs below 600 px; this section needs a mobile alternative (UI-1 decides).
- Hub, player and flashcards: inline `<style>` per page, using the site's tokens (`--blue: #287a9e`, `--ink`, `--line`…), white page, hairline borders, cards like the Mobility Lab's. The grammar reader uses `stylesheets/styles.css` (left rail and reading column, like `turkish101.html`) and its harmony classes `.back`, `.front`, `.suf`, `.stem`.
- `assets/js/turkish.js` is a classic script loaded with `defer`, exposes `window.TRK`, and also exports itself with `module.exports` when run in Node so its checker and scheduler can be tested.
- No framework and no CDN dependency unless a page truly needs one; if it does, pin an exact version on jsdelivr, as with `d3@7.9.0` elsewhere on the site.
- Every element holding Turkish text gets `lang="tr"`, so text-to-speech, hyphenation and CSS `text-transform` treat i/İ and ı/I correctly.
- Data is fetched from `/assets/data/turkish/…` with `?v=<index.version>` for cache-busting, after fetching `index.json` with `cache: "no-cache"`.
- Mobile first: works at 360 px wide, 16 px side gutters, touch targets of at least 44 px, keyboard shortcuts on desktop (Enter to check and continue, 1–6 for options), `aria-live` feedback, `prefers-reduced-motion` respected.
- If `localStorage` is unavailable, keep progress in memory and show a one-line notice that it won't be saved.
- Analytics: the site's gtag snippet only, plus at most `trk_lesson_complete` {lesson, score} and `trk_cards_session` {reviewed}. Never send typed answers.
- Links inside content (section 5.1) resolve as: unit → `turkish.html#a1-u05`, grammar point → `turkishguide.html?id=<unit>-grammar#<gp-id>`, lesson → `turkishlesson.html?id=…`, guide or interlude → `turkishguide.html?id=…`, `cards` → `turkishcards.html`. A link to something not written yet renders as plain text with "coming soon".
- `scripts/sitemap/make-sitemap.mjs` only follows links without a query string, so the hub, reader index and flashcards page enter the sitemap once `index.html` links to the hub; lessons don't, which is fine.
- GitHub Pages also publishes these Markdown files (as it does the scripts' READMEs). They contain nothing private. Never write two opening curly braces in a row, or an opening curly brace followed by a percent sign, in them: Jekyll would read it as a Liquid tag and the page would fail to build.

## 4. IDs

| Kind | Pattern | Example | File |
|---|---|---|---|
| Level | `a1`, `a2`, `b1`, `b2`, `c1`, `c2` | `a1` | `levels/a1.json` |
| Unit | `<level>-u<2 digits>` | `a1-u05` | `units/a1-u05.json` |
| Lesson | `<unit>-l<2 digits>` | `a1-u05-l01` | `lessons/a1-u05-l01.json` |
| Exercise | `<lesson>-e<2 digits>` | `a1-u05-l01-e07` | inside its lesson |
| Grammar guide | `<unit>-grammar` | `a1-u05-grammar` | `grammar/a1-u05.json` |
| Culture interlude | `<unit>-culture` | `a1-u05-culture` | `culture/a1-u05.json` |
| Grammar point | `gp-<slug>`, lowercase ASCII and hyphens | `gp-locative` | listed in CURRICULUM.md |
| Flashcard | `fc-<4 digits>` | `fc-0042` | `flashcards/fc-0001-0200.json` |
| Batch | `A1-1` … `C2-3`, `FC-1` … `FC-5` | `B1-4` | CURRICULUM.md |

- Units, lessons and exercises are numbered from 01, in order. Exercise numbers must increase; gaps are allowed.
- **IDs are frozen once a batch is logged as done**, because learners' progress is stored under them. Fix content in place; add new exercises with the next free number; if an exercise is removed, leave the gap. Never renumber.
- Grammar-point IDs are defined only in CURRICULUM.md. A point belongs to the unit that introduces it.
- Flashcard IDs are assigned once and never reused. They start equal to the rank; if the ranking changes later, ranks move and IDs stay.

## 5. Data schemas

Notation is TypeScript-like: `?` marks an optional field, `[2–6]` an array length. Unknown fields are errors. All files are UTF-8 JSON, 2-space indent, NFC-normalized text. The validator holds the same definitions; when a schema changes, change this section, its example and the validator together, then run `--examples`.

### 5.1 Common types and inline markup

```ts
type LevelId = "a1" | "a2" | "b1" | "b2" | "c1" | "c2";
type Lang    = "tr" | "en";
type Person  = "ben" | "sen" | "o" | "biz" | "siz" | "onlar";
type Pos     = "noun" | "verb" | "adj" | "adv" | "pron" | "num" | "postp" | "conj" | "interj" | "det" | "particle" | "phrase";

type Tr     = string;  // plain Turkish text, checked against the orthography rules (7.1, 7.2)
type En     = string;  // plain English text
type Rich   = string;  // English with inline markup (below)
type TrRich = string;  // Turkish with **bold** and [links](ref) only; paragraphs separated by "\n\n"
type Seg    = string;  // Turkish with "|" at morpheme boundaries: "ev|ler|de". Removing every "|" gives the plain text.
type Accept = string;  // an accepted answer, possibly with alternation syntax (6.4, 7.3)
type Gloss  = { tr: Tr; en: En };
type Reject = { answer: string; why: Rich };   // a predictable wrong answer and the feedback it gets
```

Inline markup in `Rich` (no HTML; the renderer escapes everything else):

| Markup | Meaning | Rendered as |
|---|---|---|
| `*ev*` | a Turkish word or phrase inside English text (checked as Turkish) | `<i lang="tr">` |
| `**word**` | emphasis | `<strong>` |
| `` `-(y)I` `` | a suffix, formula or notation | `<code>` |
| `[label](ref)` | link; `ref` is a unit, lesson, grammar-point, guide or interlude ID, `cards`, or an `https://` URL | `<a>` |

English emphasis uses `**bold**`, never single asterisks, because those always mean Turkish. Write a literal asterisk as `\*`.

Content blocks, used by grammar guides and interludes:

```ts
type Block =
  | { type: "p"; text: Rich }
  | { type: "list"; items: Rich[]; ordered?: boolean }
  | { type: "rule"; label?: En; lines: string[] }                  // formula lines in monospace
  | { type: "table"; caption?: Rich; head: Rich[]; cols: ("tr" | "seg" | "en" | "rich")[]; rows: string[][] }
  | { type: "examples"; items: { tr: Tr; seg?: Seg; gloss?: string; en: En; note?: Rich }[] }
  | { type: "paradigm"; title?: Rich; rows: { p: Person; tr: Seg; en?: En }[] }
  | { type: "dialogue"; lines: { who: Tr; tr: Tr; en: En }[] }
  | { type: "callout"; kind: "tip" | "pitfall" | "compare" | "culture" | "history"; title?: En; text: Rich }
  | { type: "parallel"; tr: TrRich; en: En }                       // one paragraph, Turkish beside English
  | { type: "passage"; tr: TrRich; glossary?: Gloss[] }            // Turkish text
  | { type: "quote"; tr: Tr; en: En; source: En; pd: true }        // public-domain or traditional text only (7.7)
  | { type: "image"; src: string; alt: En; caption?: Rich; credit?: En }   // src under /assets/img/, file must exist
  | { type: "see"; refs: string[]; text?: Rich };                  // cross-references
```

In a `table`, `cols` gives the type of each column's body cells; every row has as many cells as `head`. In `examples`, `seg` must equal `tr` once the bars are removed; `gloss` is an optional Leipzig-style line (`house-PL-LOC`).

### 5.5 Exercises

Common fields, then one shape per `type`:

```ts
interface ExerciseBase {
  id: string;            // "<lesson>-eNN"
  type: "mcq" | "cloze" | "translate" | "wordbank" | "match" | "listen" | "conjugate" | "morph" | "reading" | "open";
  points?: string[];     // grammar points tested: this unit's or earlier ones
  hint?: Rich;           // offered before answering
  explain?: Rich;        // shown after answering; required for mcq, cloze, conjugate and morph
}

// mcq: pick one option
{ type: "mcq"; question: Rich; context?: { who?: Tr; tr: Tr; en?: En }[];
  options: string[] /*[2–6], in optionsLang*/; optionsLang: Lang; answer: number;
  why?: { [wrongOptionIndex: string]: Rich } }

// cloze: a Turkish sentence with one "___" per blank; each blank is typed or chosen
{ type: "cloze"; text: Tr; en: En;
  blanks: ({ accept: Accept[]; reject?: Reject[] } | { options: Tr[]; answer: number })[];
  diacritics?: "strict" | "lenient" /*default strict*/ }

// translate: type a translation
{ type: "translate"; from: Lang; prompt: string /*in `from`*/; accept: Accept[] /*in the other language*/;
  reject?: Reject[]; diacritics?: "strict" | "lenient" /*default lenient*/ }

// wordbank: build the translation from tiles
{ type: "wordbank"; from: Lang; prompt: string; text: string /*canonical answer sentence*/;
  answer: string[] /*tiles in order*/; distractors: string[] /*[0–6]*/;
  accept?: string[] /*other full sentences that use only the tiles*/ }

// match: tap pairs
{ type: "match"; pairs: [Tr, En][] /*[4–6]*/ }

// listen: hear Turkish (TTS) and type it, or pick what was said
{ type: "listen"; mode: "type" | "choose"; tr: Tr; en: En;
  accept?: Accept[] /*type: extra accepted spellings; tr itself is always accepted*/;
  options?: Tr[] /*choose: [2–4], options[answer] === tr*/; answer?: number;
  diacritics?: "strict" | "lenient" /*default lenient*/ }

// conjugate: fill a paradigm
{ type: "conjugate"; base: Tr /*verb or nominal predicate*/; form: string /*slug, e.g. "past-negative"*/;
  label: Rich; cells: { p: Person; accept: Accept[] }[] /*[2–6], persons in the usual order*/;
  diacritics?: "strict" | "lenient" /*default strict*/ }

// morph: assemble a word from tiles (stem first, then suffixes)
{ type: "morph"; base: Tr /*dictionary form*/; gloss: En /*meaning to build*/;
  parts: Tr[] /*correct tiles in order; parts.join("") === result*/;
  distractors: Tr[] /*[2–6] wrong stems or suffix variants*/; result: Tr }

// reading: a Turkish text and questions about it (B1 and up)
{ type: "reading"; title?: Tr; passage: TrRich; glossary?: Gloss[]; translation?: En;
  questions: { q: Rich; options: string[]; optionsLang: Lang; answer: number; explain?: Rich }[] /*[1–5]*/ }

// open: free writing or translation, self-assessed against model answers (B2 and up)
{ type: "open"; task: Rich; source?: string; sourceLang?: Lang;
  models: string[] /*[1–3]*/; modelsLang: Lang; checklist: Rich[] /*[2–6] points to check*/ }
```

## 6. Runtime behaviour

What the build conversations implement. Constants live at the top of `assets/js/turkish.js`.

### 6.1 Path and unlocking

- Course order is A1 u01 → C2 u06; lessons in order inside a unit.
- A lesson is unlocked when the previous one is done; the first lesson of a unit when the previous unit's last lesson is done. Grammar guides and interludes are always open. `settings.unlockAll` opens everything.
- **Jump here** (`?test=<unit>`): 20 exercises drawn from every ready unit before that one whose lessons aren't done, excluding `open` and `reading`. At 80% or more first-try accuracy, those lessons are marked done with `via: "test"` and no XP.
- **Unit review** (`?review=<unit>`): 15 exercises from the unit's lessons, half from the learner's mistakes when there are enough, excluding `open`. At 80% or more, `units[id].reviewed` is set and the unit shows as mastered.
- **Practice mistakes** (`?practice=mistakes`): up to 15 exercises with `n > ok`, oldest first; a correct answer increments `ok`.

### 6.2 Lesson flow

- Show `intro` as a card, then the exercises in authored order. `listen` exercises are skipped (and not counted) when the device has no Turkish voice; a notice explains how to add one.
- After each answer, show the verdict, the canonical answer (`accept[0]`, or the options' correct answer), the `why` or `reject` feedback when it applies, and `explain`.
- A wrong exercise goes back to the end of the queue, at most twice. The lesson ends when every exercise has been answered correctly once or has used up its retries.
- Score = first-try correct ÷ exercises counted. `open` is self-assessed ("Got it", "Partly", "Not yet"), and "Got it" counts as correct. `reading` counts each question.

### 6.3 XP and streak

- +1 XP per exercise correct on the first try; +5 for finishing a lesson; +5 more for a perfect lesson; +10 for passing a unit review. Repeating a lesson earns half.
- The daily goal (`settings.dailyGoal`) is met by XP. A day counts toward the streak if the learner finishes at least one lesson or reviews at least 10 cards that day. Missing a day resets `streak.current` to 0.

### 6.4 Answer checking

`TRK.check(answer, accepted[], rejected[], lang, mode)` returns `{ verdict: "correct" | "almost" | "wrong", note?, matched? }`. The validator uses the same normalization to check accept lists.

1. **Expand** every accepted entry: `[a|b]` means exactly one of a or b; `(a)` means optional a; `(a|b)` means nothing, a or b. No nesting. Expansion is capped at 200 strings per entry.
2. **Normalize** both sides (stage 1):
   - Unicode NFC; typographic apostrophes `’ ‘ ʼ` become `'`; typographic quotes are removed.
   - Lowercase. Turkish: `İ → i`, `I → ı`, then lowercase; English: plain lowercase. Then remove any U+0307 combining dot, the residue of a non-Turkish lowercasing of İ.
   - Remove punctuation `. , ! ? ; : " ( ) … « » ¿ ¡`; turn dashes, hyphens and `/` into spaces.
   - `â → a`, `î → i`, `û → u`.
   - Collapse whitespace and trim.
   - English only: expand contractions (I'm, you're, isn't, don't, can't, cannot, won't, I'll, I've, I'd, let's, it's, that's, there's, what's…), and fold Turkish letters in names (ç ğ ı ö ş ü → c g i o s u).
3. If the answer equals a normalized **rejected** answer → `wrong`, with its `why`.
4. If it equals an accepted expansion → `correct`.
5. Ignoring apostrophes, if it equals an accepted expansion → `almost`, note "apostrophe" (*İstanbulda* for *İstanbul'da*).
6. Turkish in lenient mode only: folding `ç ğ ı ö ş ü → c g i o s u` on both sides, if equal → `almost`, note "Turkish letters".
7. English only: same number of words and exactly one word of five or more letters at edit distance 1 → `almost`, note "typo".
8. Otherwise `wrong`.

Defaults: `translate` and `listen` are lenient; `cloze` and `conjugate` are strict, because they test the letters themselves (ı versus i is a harmony error, not a typo). An exercise can override with `diacritics`. `wordbank`, `morph`, `match`, `mcq` and `reading` compare tiles or indexes, not text.

### 6.5 Text-to-speech and typing

- `speechSynthesis` with `lang = "tr-TR"` and the first voice whose `lang` starts with `tr`. Speed `settings.ttsRate`; a slow button plays at 0.6.
- A speaker button sits on every `listen` exercise, every Turkish prompt, lesson vocab and flashcards.
- Typed answers get a bar of Turkish letters, `ç ğ ı ö ş ü`, with a shift key for `Ç Ğ İ Ö Ş Ü`. Input fields use `lang="tr"`, `autocapitalize="off"`, `autocorrect="off"` and `spellcheck="false"`.

### 6.6 Flashcard scheduling (Anki SM-2, default settings)

Constants: learning steps 1 min and 10 min; relearning step 10 min; graduating interval 1 day; easy interval 4 days; starting ease 2.50; minimum ease 1.30; hard multiplier 1.2; easy bonus 1.3; lapse multiplier 0 (new interval 1 day); maximum interval 3,650 days; leech at 8 lapses.

- **New or learning card.** Again → back to step 0. Hard → repeat the current step (on the first step, wait the average of the first two steps). Good → next step; after the last step the card graduates to review with `ivl = 1`. Easy → graduates at once with `ivl = 4`.
- **Review card** answered `d` days late (`d ≥ 0`):
  - Hard: `ivl' = max(ivl + 1, ivl × 1.2)`, ease − 0.15
  - Good: `ivl' = max(hard' + 1, (ivl + d/2) × ease)`
  - Easy: `ivl' = max(good' + 1, (ivl + d) × ease × 1.3)`, ease + 0.15
  - Again: lapses + 1, ease − 0.20, state relearning at step 0, and the review interval becomes 1 day; at 8 lapses set `leech` (show it in the deck browser; don't suspend).
- Round intervals to whole days and cap them at 3,650. From 3 days up, add a random fuzz of ±5% (at least ±1 day).
- **Relearning card.** Again → step 0; Good on the last step → back to review with the new interval; Easy → back to review with that interval + 1.
- **Due.** Learning cards are due at their exact time. Review cards are due on their day, from `dayStartHour`.
- **Daily session.** Due learning cards first, then due reviews (oldest first, up to `reviewsPerDay`), with new cards mixed in, one after every few reviews, up to `newPerDay`. New cards come in rank order; with `onlyTaughtWords`, only cards whose `unit` is done.
- **Directions.** `tr-en` (see Turkish, recall English) and `en-tr` (see English and the part of speech, recall Turkish) are scheduled separately. A word's `en-tr` card is introduced only after its `tr-en` card has graduated, and once one direction has been answered, the other waits until the next day (Anki's sibling burying).
- Self-graded, as in Anki: show the front, "Show answer", then Again, Hard, Good and Easy with the next interval printed on each button. The back shows glosses, the example with its translation, the forms and the note.

## 7. Content style rules

### 7.1 Turkish orthography

- Standard Istanbul Turkish, spelled as in the TDK *Yazım Kılavuzu* and the *Güncel Türkçe Sözlük* (sozluk.gov.tr). When unsure about a spelling, check sozluk.gov.tr rather than guessing.
- Only the 29 Turkish letters, plus â, î and û where TDK writes them: words they distinguish (*hâlâ* still / *hala* aunt, *kâr* profit / *kar* snow, *âşık* lover / *aşık* knucklebone), loanwords where they mark a palatal k, g or l (*dükkân*, *kâğıt*, *rüzgâr*, *hikâye*), and the adjective suffix -î (*millî*, *resmî*). q, w and x only in foreign names.
- Apostrophe before suffixes on proper names, abbreviations and numerals: *İstanbul'da*, *Ayşe'nin*, *TDK'nin*, *1923'te*, *3'ü*. No apostrophe on common nouns, on derivational suffixes (*İstanbullu*, *Türkçe*), or on names of institutions and organizations (*Türk Dil Kurumuna*, *Türkiye Büyük Millet Meclisinde*). The suffix follows the pronunciation of a foreign name (*Bordeaux'da*).
- The question particle *mI* is always written apart and carries the personal ending (*geliyor musun?*). The conjunction *dA* and the conjunction *ki* are written apart; the suffixes *-DA* and *-ki* are attached (*evde de*, *evdeki*). Fused exceptions: *belki, çünkü, sanki, hâlbuki, oysaki, mademki*.
- Month and day names take a capital only inside a full date (*29 Ekim 1923*, *30 Ağustos Pazartesi*); otherwise lowercase (*ekimde*, *pazartesi günü*).
- Sentences start with a capital letter and end with punctuation. In JSON, the Turkish apostrophe is always `'` (U+0027), never `’`; dialogue quotes in Turkish text use “ ”.

### 7.2 İ and ı

- Four letters: i/İ (dotted) and ı/I (dotless). *İstanbul*, *İzmir*, *İngilizce*, *İyi* at the start of a sentence; *Isparta*, *Iğdır*, *Irmak*, *Işık*, *Ilık* with a dotless capital. Never write *Istanbul* in Turkish text (in English text the usual English spelling, *Istanbul*, *Izmir*, is fine).
- Never produce Turkish capitals with a plain `toUpperCase()` or lowercase with `toLowerCase()`: in JavaScript use `toLocaleUpperCase("tr-TR")` and `toLocaleLowerCase("tr-TR")`, and in CSS put `lang="tr"` on any element with `text-transform`. A plain `"İ".toLowerCase()` produces `i` + U+0307, which the validator rejects.
- When writing JSON, type Turkish capitals directly; don't derive them in code.

### 7.3 Accepted answers

- `accept[0]` is the **canonical answer**, shown after a mistake: a correct, natural, punctuated sentence, written as plain text without alternation syntax. Further entries may use `[a|b]`, `(a)` and `(a|b)` (6.4). Every expansion must be a correct sentence; read them all. *Mehmet is [at|in] (the) office* would accept "Mehmet is in office", which means something else.
- List every natural translation a careful learner might give, not just the textbook one:
  - **Pronouns.** Turkish drops subject pronouns: accept the sentence with and without them (*Evdeyim* / *Ben evdeyim*).
  - **Third person.** *o* is he, she or it: accept all three unless context decides (`[he|she|it]`).
  - **You.** For English prompts with **you**, accept *sen* and *siz* forms unless the prompt says "(singular)", "(plural)" or "(formal)".
  - **Articles.** Turkish has none: accept English with *a* or *the* where both are possible; definiteness shown by the accusative decides when it applies (*Kitabı okudum*: **the** book).
  - **Tenses.** The aorist maps to the English simple present or *will*; *-(I)yor* maps to the present continuous and sometimes the simple present.
  - **Word order.** Accept the natural Turkish orders, not every permutation.
  - **Spelling.** Accept British, Canadian and US spellings (`[colour|color]`) and digits or words for numbers (`[two|2]`).
- Write English answers in full forms (*I am*, *do not*): the checker expands contractions in the learner's answer.
- `reject` lists predictable wrong answers with a targeted *why* (wrong case, wrong harmony, missing ending). A rejected answer must never also be accepted; the validator checks this.
- Typed answers stay short: for `cloze` usually one word or one suffix, for `translate` at most about 12 words at A1–A2.
- Never accept something wrong just to be kind; the `almost` verdicts already cover typos and missing Turkish letters.

### 7.4 Tone and English

- Friendly, precise and short. Second person ("you"). No hype and no exclamation marks in explanations.
- Canadian English spelling, as on the rest of the site (colour, centre, labelled, organize).
- `hint` ≤ 25 words, `explain` and `why` ≤ 40 words, `intro` ≤ 60 words. Guides can say more, but every paragraph has to earn its place.
- Name grammar in plain English first and give the Turkish term once in brackets (vowel harmony (*ünlü uyumu*), buffer letter (*kaynaştırma harfi*), consonant softening (*ünsüz yumuşaması*)).
- Write suffixes with a leading hyphen. Use the archiphoneme notation (A, I, D, C, K, buffers in brackets) from a1-u03 on; before that, spell the variants out (-lar/-ler).
- French or English comparisons only in a `callout` of kind `compare`, and only when they really help.

### 7.5 Lessons and exercises

- Each unit has the number of lessons CURRICULUM.md gives for its level. Lessons 1 to 3 (or 1 to 2 at C1–C2) each focus on one or two grammar points with the unit's vocabulary; the last lesson mixes everything with a short dialogue or text.
- Exercises per lesson: 10–14 at A1–B2, 6–12 at C1–C2.
- At least four exercise types per lesson (three at C1–C2). From A1 to B1, every lesson has at least one `listen`, and translation (`translate` or `wordbank`) in both directions.
- `match` in the first lesson of each unit at A1–A2, for the new words. `conjugate` whenever a lesson introduces verb forms; `morph` for suffix chains.
- `reading`: at least one per unit from B1. `open`: at least one per unit from B2.
- A word is taught (listed in a lesson's `vocab`) before it appears in an English → Turkish prompt or as a typed answer. Recognition exercises (Turkish → English, `listen` with `choose`) may use a few untaught words if the meaning is clear.
- Exercises never use grammar from later units, except fixed phrases listed as vocabulary (*Benim adım…* in a1-u01).
- Turkish sentences must be things a native speaker would actually say: natural word order, pronouns dropped unless contrastive, everyday vocabulary. No calques of English.
- People in sentences: a varied cast of Turkish first names (Ayşe, Mehmet, Elif, Can, Zeynep, Emre, Deniz, Selin, Murat, Fatma, Ali, Ece…), sometimes foreign visitors. No real living people, no politics, no religion beyond neutral cultural facts, no stereotypes about regions, ethnic groups or genders.

### 7.6 Grammar guides

- Length: about 900–2,000 words at A1–A2 and 1,200–2,500 from B1.
- One section per grammar point, in CURRICULUM.md order: explanation, the rule or table, at least four examples (`examples` with `seg` on the suffixes being taught), and pitfalls.
- A full `paradigm` (positive, negative and question) for every new verb form, on a regular verb, plus a second verb when stems change. One exception, set by CURRICULUM.md: the present of "to be" (a1-u03) is shown positive only, because its negative *değil* and the question particle *mI* are introduced in a1-u04, whose guide gives them in full.
- `summary` with 3–8 takeaways. Cross-reference earlier units with links instead of re-explaining them.

### 7.7 Interludes, history and copyright

- Length: 350–600 English words at A1–A2 (plus the Turkish mini-read, using only grammar taught so far); at B1, 300–500 words in each language; from B2, 300–800 Turkish words with a glossary (and a two- or three-sentence English summary at B2).
- **Factual and neutral.** Dates, names and places checked against at least two reliable sources (encyclopedias, UNESCO, museums and official sites, academic works), listed in `sources` with URLs. Legends are labelled as legends ("according to Evliya Çelebi…"). Contested subjects are described with attributed views, not adjectives of praise or blame, and are not avoided when they are central to the topic. Religious holidays and practices are described as cultural facts.
- **Copyright.** No song lyrics. No poems or prose under copyright: quote only texts that are traditional (folk tales, proverbs, manis, riddles) or by authors who died before 1956 **and** first published before 1931 (Yunus Emre, Karacaoğlan, Pir Sultan Abdal, the Divan poets, Namık Kemal, Halit Ziya's early novels, Ömer Seyfettin). Translations of quoted texts are our own. Modern authors and filmmakers are described and summarized, never quoted. Every `quote` block carries `source` and `pd: true`.
- No images except Grégoire's own photos already in `/assets/img/` (for example `istanbul1.webp`), with `alt` text.

### 7.8 Flashcards

- The deck is the 1,000 most useful lemmas of modern Turkish, roughly in frequency order: no proper nouns, no inflected forms, set phrases only when very common (*teşekkür ederim* as a phrase card, *rica etmek* as a verb).
- **FC-1 settles the source** for all five batches: if a public frequency list with a clear licence can be read, use it for the order (lemmatized and cleaned by hand) and credit it in `source`; if none is usable, say so to Grégoire and propose an alternative before writing cards. `source` must describe the method honestly; never claim corpus ranks that weren't computed.
- Example sentences are original, natural and short (≤ 10 words), mostly A1–A2 grammar, and use the word in its most common sense.
- `en` gives the most common meanings first, up to four. Verbs: "to …". Add `note` for false friends, register (formal, colloquial) or irregularities.

```
   add --strict to turn warnings into errors, --quiet to hide warnings
```

**Errors** (must be fixed): invalid JSON or schema; wrong or duplicate IDs; file names that don't match IDs; references to missing units, lessons, guides, interludes, grammar points or cards; units, titles or grammar-point lists that differ from CURRICULUM.md; grammar points used before the unit that introduces them; guide sections that don't cover the unit's points in order; accept lists with syntax errors, duplicates or overlaps with `reject`; `cloze` blanks, `wordbank` tiles, `morph` parts or `seg` text that don't add up; forbidden characters (U+0307, `’` in Turkish, HTML tags); a stale `index.json`.

**Warnings** (fix, or explain in the log): sizes and mixes outside the targets in section 7; Turkish words starting with a dotless *I* that look like they need *İ*; a question particle glued to its verb (*gelirmisin*); non-Turkish letters in Turkish text; flashcard examples that don't seem to contain their word; interludes with fewer than two sources.
